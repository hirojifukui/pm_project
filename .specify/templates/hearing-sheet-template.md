# 業務ヒアリングシート: [業務名]

> **このシートの使い方**
>
> - 業務を知っている人から話を聞き、その内容をこのシートに書き込みます。書くのは「今の業務」と「こうなってほしい姿」です。画面やデータベースのことは書きません。
> - 空欄があってもかまいません。分からないことは推測で埋めず、「13. 未確定事項」に書き出します。
> - 各行の ID（AS-01、R-01 など）は消さないでください。仕様書から「出典」として参照されます。行を足すときは続きの番号を振り、行を消しても番号は振り直しません。
> - 記入が終わったら、`docs/requirements/<業務名の英語>-hearing.md`（例: `docs/requirements/travel-expense-hearing.md`）として保存し、Claude Code で次のように実行します。
>
>   `/speckit-specify docs/requirements/travel-expense-hearing.md を元に仕様書を作成`
>
> **表の書き方**
>
> - 1つのマスの中で改行しないでください。複数書くときは「、」で区切ります。
> - マスの中に `|`（縦線）を書かないでください。表が崩れます。
> - 「8. 権限」に役割の列を足すときは、2行目（`|:---:|` の行）にも同じ数だけ `:---:|` を足します。
>
> **聞き取りのコツ**
>
> - 「普段どうしていますか」の次に「うまくいかないのはどんなときですか」と聞きます。例外は2つ目の質問で出てきます。
> - 「ベテランが気をつけていること」「新人がよく間違えること」を聞きます。規程に書かれていないルール（暗黙のルール）はここから出てきます。
> - 数字は「だいたい」でよいので必ず聞きます（件数、金額、日数、時間）。
> - ルールを聞いたら「それはどこに書いてありますか」と聞き、根拠（規程名と条番号、または「慣習」）を記録します。
> - 本人が自分の申請を承認・確定してしまう場面がないか、役割ごとに確認します。
